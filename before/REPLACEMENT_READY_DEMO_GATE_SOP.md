# Replacement-ready Demo Gate SOP

> 用途：把「看起来像 Demo」改成「老板今天就愿意拿来替换当前展示页的 £99 AS-SHOWN 成品」。适用于所有新建、方向级重做，以及未发送/重截图/再次外联前重验的静态单页 Demo。
>
> 这是一套把既有 `Demo Production v1.2`、`Research-to-Demo Activation Matrix`、资产台账与双视口 QA 变成可核对闭环的执行 Gate；不改变客户素材权利、部署、外联、交付或生产授权边界，也不要求复制客户后台、支付、库存或服务端表单。

## 0. 唯一判断与状态

唯一问题：**客户把当前官网、目录页或社媒落地页换成这张页面后，核心业务理解、信任内容和可行动路径是否完整保留且明显更好？**

```text
REPLACEMENT-READY PRE-CODE = PASS / FAIL / BLOCKED
REPLACEMENT-READY FINAL = PASS / FAIL / BLOCKED
```

- `PASS`：每个高价值现有内容、事实或动作路径均已在最终页面实际落位，或有明确且合理的合并/外链/排除理由；现站壳与客户真实品牌已区分；Desktop 与 390px 证据均通过。
- `FAIL`：存在未处置高价值项、假功能、死链、无理由丢失的联系/预约/地图/社媒路径，把平台/建站模板视觉误作客户品牌，或任一视口的内容、图片裁切、可读性或信息密度不成立。
- `BLOCKED`：公开页面无法读取、当前路径无法核验或证据不足。只能继续研究；不得用猜测填充为 PASS。

`CLIENT-SHOWABLE DEMO = PASS` 的必要条件是 `REPLACEMENT-READY FINAL = PASS`，但不等于部署、发送、客户授权或最终源码/资产转让通过。

## 1. Gate A — 现状基线与保留清单（先于视觉）

先真实打开客户官网、官方社媒和当前主要目录/地图页，在 Desktop 与约 390px 记录 URL、访问日期与基线截图。然后形成下表；没有现站时，官网/社媒/目录的组合就是基线。

| Baseline ID | 当前来源与版位 | 来源/品牌判断 | 客户/访客价值 | 当前内容或动作 | 处置 | 目标 section + selector | 最终核对 | 排除/合并理由 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- |
| B-01 | 官网 Hero / 官方 IG / Maps | `CUSTOMER BRAND` / `HOST-TEMPLATE` / `PLATFORM-SHELL` / `THIRD-PARTY` | 高 / 中 / 低 | Logo、服务、真实图、评价、地图、电话、email、社媒、表单、预约等 | `CARRY` / `CONSOLIDATE` / `EXTERNAL-LINK` / `EXCLUDE` |  | `PASS` / `FAIL` | 仅 `EXCLUDE` 或 `CONSOLIDATE` 必填 |

### 高价值项：必须逐项处置

1. Logo、商户名称、地区/地址与核心服务；
2. 客户公开的真实门店、作品、食物、团队、设备或服务场景图；
3. 已公开可复核的评价、资质、案例、营业/到店提示及其他信任输入；
4. 电话、公开业务邮箱、方向/地图、官方社媒；
5. 当前最主要的行动路径：联系、预约、点餐、询价、购买、导航或表单；
6. 当前站中对访客有明确价值的 FAQ、菜单/服务说明、配送/到店、政策或第三方流程。

不要求把每个旧页面机械搬到单页；允许合并信息、收束成一个核心 CTA 或保留现有第三方入口。但**不允许因为它不是视觉素材就遗漏**。每项 `EXCLUDE` 必须说明为何对当前 £99 静态核心切片无价值、已过时/冲突、不可安全呈现，或已被哪个更完整的行动路径替代。

### 现站真实品牌与替换价值判定

- `HOST-TEMPLATE` / `PLATFORM-SHELL`（例如建站工具的 Coming Soon、默认色块、通用星空或默认表单）只能作为现状可用性证据，**不得**直接推导成客户色板、字体、Hero 气质或页面 Soul；客户品牌应优先从官方 Logo、真实照片、官方社媒、稳定业务文案与可归属服务事实提取。无法区分时固定 `REPLACEMENT-READY PRE-CODE = BLOCKED`。
- Track W 在任何视觉设计前必须写出 `5-second Before/After Commercial Contrast`：客户在不读长文案时，为什么能更快理解业务、看到何种可信证据、并走向哪一个真实下一步。若现站已经完整保留 Logo、核心服务、Proof、地点和行动路径，而候选只能提供字体、颜色、间距、一般 SEO/性能或小型移动端修补，固定 `NO MEANINGFUL REPLACEMENT THESIS — DO NOT CREATE DEMO`；回到候选筛选，不得用重新设计硬制造购买理由。

## 2. Gate B — 研究、资产和现状的单一映射

在 `PRE_CODE_DECISION.md` 中使用 `DEMO_CONTENT_ACTIVATION_TEMPLATE.md` 的 Activation Matrix，并为每个高价值 `Baseline ID` 补上对应 `Item ID`。每项只能有一个处置：

- `DIRECT USE`：登记来源的 A/B 级 Logo、照片、项目、稳定业务事实；
- `FACT/PARAPHRASE USE`：准确的服务、评价、tips、业务说明；
- `LOCATION/VISIT USE`：地址、路线、地图、到店提示、营业相关信息；
- `CONCEPT VISUAL REPLACEMENT`：缺少真实可用图的独立视觉回退，不能冒充客户作品；
- `TIME-SENSITIVE VERIFY/REPHRASE`：菜单、价格、库存、活动、营业时间等；
- `EXCLUDE`：只可附具体原因，不能用“素材不足”或“以后补”。

预编码必须满足：

```text
高价值 Baseline 项处置率 = 100%
高价值 Activation 项落位率 = 100%
未解释的 Logo / 真实图片 / 地图 / 社媒 / CTA / 联系路径 = 0
REPLACEMENT-READY PRE-CODE = PASS
```

这里的「落位」不是只写在台账：必须写明目标 section、内容职责和预期 selector。现有页面图、真实食物/门店/团队/项目、客户反馈与地址定位等，优先作为实际页面内容，而不是仅作研究灵感。

真实客户资产不得只在 Hero 使用一次就被后续通用文字/色块取代。每项适合的真实图或事实必须先决定其在 `HERO / SERVICE / PROOF / PROCESS / LOCATION / CLOSING` 中的商业角色；只有该角色没有可用的 A/B 级真实资产时，才可使用有明确概念边界的替代视觉。先选通用 Hero、再补资产，或用概念图覆盖已登记但未处置的客户官方/商户可归属资产，固定 `REPLACEMENT-READY PRE-CODE = FAIL`。

## 3. Gate C — 可替换的信息与行动架构

最终静态单页必须实现一个完整、可卖的访客闭环：

```text
5 秒识别生意 → 看懂核心服务/产品 → 看见可信证据 → 知道在哪里/如何到店或联系 → 能完成真实下一步
```

### 必须检查

| 维度 | PASS 条件 |
| --- | --- |
| 识别 | Hero 在不读长文案时能看出客户行业、业务气质与核心服务；商户名/Logo 在有可用来源时实际出现。 |
| 内容 | 2–3 个与客户事实一致的服务/产品切片、至少一个相关 Proof/地点/过程/作品/评价输入，以及 Bottom 40% 的继续浏览与联系理由。 |
| 图片 | 客户可用真实图优先进入 Hero 之外的多个商业节拍；不足处使用有清楚概念边界的原创视觉，不得用单张 Hero 加连续纯文字区交差。 |
| 地点 | 地址、服务地区或到店信息在适用时实际可见；地图/导航使用真实外链或明确的地址行动，不能做不可用装饰。 |
| 联系 | 电话、公开业务邮箱和其他已知高价值联系路径没有无故丢失；`tel:`、`mailto:`、WhatsApp 等链接必须真实可用。 |
| 社媒 | 当前官方社媒是客户主要展示/信任入口时，保留真实官方跳转；若合并或排除，台账写明理由。 |
| 现有表单/预约/点餐 | 禁止伪造静态“提交成功”表单或重建服务端能力。保留客户原有真实第三方 URL，或以明确、可工作的电话/mailto/外部预约行动替代；替代关系必须在 Baseline 表中可追溯。 |
| CTA | CTA 文字、目标 URL 与页面承诺一致；每个主按钮经实际点击核验，无 `#`、空链接或未完成导航。 |
| 密度与节奏 | 每个大 section 都有明确的客户信息、真实视觉、Proof 或行动职责；不得把有限内容拆成大面积空白、连续暗/纯色块、等权卡片或只靠大字的“高级感”。若删去装饰后仍无法说出该 section 的客户价值，固定 `FAIL — REDESIGN DIRECTION`。 |

任何方向若主要依赖通用行业套路（如编号服务卡、无客户含义的巨大编辑式标题、宠物 SPA 色板、泛化住宅 Hero、连续暗块或等宽模板网格），即使视觉整洁也不得通过 Gate C；必须在 `PRE_CODE_DECISION.md` 写明所拒绝的默认套路及替代它的客户特异事实、素材和页面节奏。

## 4. Gate D — DOM、图片裁切与双视口回填

编码后回填 Activation Matrix 和 Baseline 表。每个 `CARRY`、`CONSOLIDATE` 或 `EXTERNAL-LINK` 项必须在最终 HTML 实际存在，并写入文件/selector、链接目标与截图位置。

固定以最终本地页面核验 `1440×900` 与 `390×844`：

- 客户 Logo、真实资产、主要服务、Proof/地点和 CTA 在应出现的视口可见且层级正确；
- 每张已映射图片逐张检查：主体未被误裁、关键人物/食物/作品没有被切掉、文字无遮挡、清晰度足够、不会重复凑数；
- 真实地图/导航、电话、email、社媒、外部预约/点餐/表单路径逐个点击或检查最终 href；
- 无占位文案、空白关键区、假表单、死链、暴露内部治理文本，且没有以“正式版再补”制造残缺。
- 每一张 `1440×900` 与 `390×844` 最终证据必须来自实际浏览器；Desktop 首屏高度不得因未约束的图片或容器而吞没主要业务/CTA，Mobile 不得以“约 390px 未复核”进入 PASS。
- 浏览器、HTTP 或抓取工具超时只能记录为当前证据/工具 `BLOCKED`，不能推断客户页面无法访问、客户路径失效或最终页面已通过；应以可复核的实际页面、DOM 或独立浏览器证据补齐。

轻微单点裁切、对比度、拼写或链接修复可短修。涉及遗漏的客户资产/路径、Hero 架构、服务层级、页面节奏或跨 Demo 同构，固定 `FAIL — REDESIGN DIRECTION`，回到 Gate A–C，而不是堆 P2 补丁。

## 5. Gate E — 独立替换验收

制作 Owner 之外的 Reviewer 只看基线、最终页面、DOM/链接清单与两张视口证据，逐项回答：

1. 若客户明天把当前展示页替换为它，是否无故失去任何核心服务、信任内容或行动路径？
2. 客户公开可用的高价值 Logo、图片、地点、评价/事实、社媒和联系路径，是否都在页面或有具体处置？
3. 这张页面是否是能直接交付的 £99 AS-SHOWN 成品，而非需要客户先指出遗漏、再补成正式版的 Demo？
4. 相比现状，能否具体说出理解、信任或询盘上的增量，而不只是“更好看”？
5. 是否已把平台临时壳、默认表单或宿主视觉排除在客户品牌判断之外，并让真实客户 Logo、素材和业务事实主导页面？
6. 在两个指定视口中，是否不存在由空白、过高图片、连续色块或等权卡片造成的“内容显得不够、页面不像可替换成品”的问题？

全部为「是」，且 Gate D 无 P0/P1 缺陷，才可写：

```text
REPLACEMENT-READY FINAL = PASS
CLIENT-SHOWABLE DEMO = PASS（仍须满足其他现有 Gate）
```

## 6. 每个客户必须留下的最小证据

```text
CUSTOMER_PUBLIC_INTELLIGENCE.md
ASSET_INVENTORY.csv
PRE_CODE_DECISION.md（含 Activation Matrix、Baseline 表和 Purchase Thesis）
最终页面文件与 1440×900 / 390×844 截图
REPLACEMENT-READY FINAL 结论、Reviewer、剩余 P0/P1 = 0
```

可以复用的是研究表结构、验证脚本、通用无品牌组件和 QA 方法；不得复用客户 Logo、图片、文案、色板、Hero 构图、服务层级或页面节奏。SOP 的目标是一次成型，不是让所有客户页面长得一样。
